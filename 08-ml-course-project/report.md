# 电信客户流失预测 · 机器学习课程项目

## 摘要

客户流失是订阅制业务的核心问题。本项目基于 2000 条电信客户样本，构建从数据清洗、特征编码到模型比较的完整流程，对比逻辑回归、随机森林与梯度提升树三种模型，并用 5 折交叉验证评估稳定性。逻辑回归在召回率与 F1 上表现最好（Recall 0.7714、F1 0.6646、AUC 0.7646），更适合“宁可多挽留、不可漏掉高风险客户”的业务场景。

## 1. 问题与目标

- **业务问题**：哪些客户即将流失？哪些因素影响最大？运营团队应该优先干预谁？
- **建模目标**：二分类预测 `churn`（1 = 流失），输出概率用于客户分层
- **评价指标**：AUC、Recall、F1 为主，Accuracy 为辅（流失样本占 35%，不算极端不平衡，但仍需关注召回）

## 2. 数据

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenure_months` | 数值 | 在网月数 |
| `monthly_charges` | 数值 | 月费用 |
| `total_charges` | 数值 | 累计费用 |
| `support_calls` | 数值 | 客服呼叫次数 |
| `contract` | 类别 | 月付 / 一年 / 两年 |
| `internet_service` | 类别 | 光纤 / DSL / 无 |
| `payment_method` | 类别 | 电子 / 邮寄 / 银行 |
| `online_security` | 类别 | 是否开通安全服务 |
| `churn` | 目标 | 是否流失 |

- 样本量：**2000**
- 流失率：**34.95%**
- 数据来源：**合成样本**（`src/generate_data.py` 生成），用于演示完整流程；原始课程数据未随文件提供。

### 探索性发现

| 维度 | 流失率 |
|---|---:|
| 月付合同 | **42.62%** |
| 一年合同 | 26.07% |
| 两年合同 | 24.67% |
| 光纤用户 | **41.35%** |
| DSL 用户 | 28.35% |

- 流失客户平均在网 **26.5 个月**，未流失客户 **41.1 个月**
- 流失客户月均费用略高（72.7 vs 67.9），客服呼叫更多（1.32 vs 1.13）

## 3. 方法

### 预处理
- 数值特征：中位数填补 + 标准化
- 类别特征：众数填补 + One-Hot 编码
- 全部封装为 `ColumnTransformer` + `Pipeline`，避免测试集信息泄漏

### 模型
| 模型 | 关键设置 |
|---|---|
| 逻辑回归 | `class_weight='balanced'`，max_iter=2000 |
| 随机森林 | 300 棵树，min_samples_leaf=3，balanced |
| 梯度提升树 | sklearn 默认参数，random_state=42 |

- 训练/测试：8:2 分层抽样
- 稳定性：5 折分层交叉验证（AUC）

## 4. 结果

| 模型 | Accuracy | Precision | Recall | F1 | AUC | 5-fold CV AUC |
|---|---:|---:|---:|---:|---:|---:|
| **逻辑回归** | **0.7275** | 0.5838 | **0.7714** | **0.6646** | **0.7646** | **0.7603** |
| 随机森林 | 0.6950 | 0.5625 | 0.5786 | 0.5704 | 0.7327 | 0.7331 |
| 梯度提升树 | 0.7175 | **0.6517** | 0.4143 | 0.5066 | 0.7412 | 0.7296 |

**解读**：
- 逻辑回归召回最高（77.14%），漏掉的流失客户最少，适合作为召回优先的基线
- 梯度提升树精确率最高（65.17%），但召回只有 41.43%，会漏掉近六成流失客户
- 三个模型 AUC 差距不大（0.73–0.76），说明特征信息量有限，提升空间更多在特征工程与数据质量

| 特征 | 重要性 |

## 5. 业务建议

1. **月付合同 + 光纤用户**是流失高风险组合，优先推送续约优惠
2. **在网前 12 个月**是挽留关键窗口，新客 onboarding 需要加强
3. **客服呼叫次数 ≥ 2** 的客户应进入主动回访名单
4. 用预测概率做三层分层：高风险（>0.7）人工外呼、中风险（0.4–0.7）短信/优惠券、低风险正常运营

## 6. 局限

1. 数据为合成样本，指标不代表真实业务表现
2. 未做特征交叉、目标编码与超参数搜索，模型仍有提升空间
3. 未考虑时间维度（如近 3 个月消费变化），而流失往往是动态过程
4. 阈值固定 0.5，实际业务应按挽留成本与客户价值调整
